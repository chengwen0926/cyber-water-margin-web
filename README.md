# 赛博水浒入职日

本地单机 HR 审查模拟游戏。前端 Next.js（像素风 Macintosh 桌面），后端 FastAPI，数据以本地 JSON 文件持久化。详见 `specs/specs.md` 与 `specs/design.md`。

## 开发环境

一键启动（同时拉起前后端，Ctrl+C 一并停止）：

```bash
uv run python launch.py
```

或分别在两个终端启动：

```bash
# 终端 1：后端 (FastAPI, http://localhost:8000)
cd backend
uv run uvicorn main:app --reload --port 8000

# 终端 2：前端 (Next.js, http://localhost:3000)
cd frontend
npm run dev
```

前端通过 `NEXT_PUBLIC_API_BASE_URL` 环境变量指向后端地址，默认 `http://localhost:8000`（可复制 `frontend/.env.local.example` 为 `frontend/.env.local` 自定义）。

## 后端测试

```bash
cd backend
uv run pytest
```

## 游戏流程

1. 登录（装饰性，无真实鉴权）
2. 点击菜单栏「进入下一天」生成当日候选人队列
3. 在「邮箱」下载简历附件 → 进入「档案」
4. 在「档案」查看简历字段、使用「一键发现问题」、提交通过/拒绝判定
5. 在「医疗库」查看体检原件、与简历比对
6. 在「聊天」与领导/候选人对话，处理领导下达的特殊密令
7. 点击「结束今天」触发当日结算与惩罚判定

## 阅读状态

邮箱、档案、医疗库和聊天的侧边栏均提供「全部 / 未读 / 已读」筛选，列表仅显示匹配内容；切换筛选会清空当前详情。打开未读内容后，该项移入已读列表，详情保留供继续操作，不会自动打开下一项。列表同时显示「已读 / 未读」状态。只有内容加载成功并显示在当前活动窗口中，才会标为已读；下载附件、审查判定与阅读状态互相独立。阅读记录保存在 `save.json` 的 `read_receipts` 中，刷新页面或重启服务后保留。

聊天按联系人和消息版本记录阅读状态，新对话节点、新一天或领导新来电会重新显示未读；共用脚本的候选人不会共用阅读记录。桌面聊天图标显示未读会话数量。旧存档没有阅读历史，首次启用时现有内容按未读处理。

## 视频面谈界面

聊天详情从上到下显示角色通话画面、双方聊天记录和当前可选回答。点击回答时显示发送中消息，服务端确认后保存玩家原文与对方回复；聊天记录自动滚动到最新消息。记录保存在 `chat_transcripts`，按联系人与脚本隔离，切换或刷新后可以恢复。旧存档只显示已保存的当前节点，不补造历史回答。当前角色视频素材尚未接入，视频区域显示角色头像或占位画面。
